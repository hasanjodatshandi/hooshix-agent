# Production topology, deployment, SLO, release and disaster recovery

**Requirements:** P-15/19/20/21/24. Extend the **current HooshiX platform operating model**. Do not replace current `production-single-server` profile with EAAP's historical HA/Kubernetes suggestion or claim that HA/air-gap is already implemented. Actual deployment requires a separate authorized production commissioning program.

## Supported deployment profiles
| Profile | Required structure and truthful claim | Authority/gate |
|---|---|---|
| Developer WSL/local integrated | Existing local isolated DB/roles, Redis/Kafka as currently configured, exact service versions and synthetic fixtures; no customer data | `make local-runtime-up/status` only under current repo guidance; readiness not production |
| Local production-fidelity kind/staging | Existing Kyverno CEL, Calico/Istio, Traefik/WAF, observability and pinned components; add EAAP workers/gateway/model in reviewed limited capacity | `make production-fidelity-up/verify` with current accepted resource constraints; not actual Production |
| Selected production-single-server | One physical host / current K3s single-node and per-service release; new EAAP workloads must fit measured CPU/RAM/disk/GPU, IOPS, concurrent device sessions, log/evidence retention and network; no node HA | current ADR-0042/0043/0044 plus security, backup, complete-stack load/restore evidence, owner commissioning |
| Production HA expansion | Multi-failure-domain placement/replication only after owner reactivation and reviewed current HooshiX HA topology; separate DB/queue/device gateway/inference failover tests | HA ADR, exact cost/capacity/RPO/RTO measured, promotion/rollback |
| Connected on-prem/restricted-egress | all external providers/connectors require allowlisted egress/classification policy; secret/service identity, certificate renewal and offline fallback | real policy and packet/egress tests |
| Fully air-gapped | private image/model/artifact registries, offline pinned dependency/signature/vulnerability feeds, self-hosted identity/DNS/NTP, local model + local-only connector/workflow, signed offline install/update/recovery; no runtime internet/license/telemetry | physical network-isolation exercise with outbound packet capture and signed offline upgrade/rollback |

## Workload packaging / resource controls
Each added deployable only after approved owner/ADR: OCI image, exact pinned digest and SBOM, unprivileged non-root, read-only filesystem where compatible, no privilege escalation, dropped capabilities, RuntimeDefault seccomp, finite CPU/memory/ephemeral storage, dedicated service account/deny-by-default NetworkPolicy, startup/readiness/liveness and graceful drain. App-specific secret refs outside Git/images/Helm values. Device Gateway long-lived connections need drain/affinity/reconnect and bounded stream count; do not use sticky browser auth as routing authority. Browser workers run isolated nonprivileged sessions with per-tenant resource bound; deny host filesystem/network by default. Inference/GPU workers have admission queue, model asset integrity, GPU memory reservations, CPU fallback only if performance/security approved.

## Release and progressive activation
1. Pin source commit and signed/reproducible build via existing HooshiX protected CI and service-owned gates. Semgrep/Gitleaks/OSV advisory, Gradle integrity/ArchUnit, frontend tests and neutral schema compatibility precede release.
2. Build final image once; Syft CycloneDX/Grype correlate exact image, Cosign sign digest and provenance, Kyverno admit only policy-approved digest/identity. Exact artifact promoted from staging to prod; no mutation of prod image after verification.
3. Schema expand and compatibility tests before app deployment; publish new contracts in versioned neutral registry; stage under feature flag disabled or read-only; validate live permission/egress/device allowlists and model evaluation; canary by tenant/capability, bounded rollback trigger and observed stability.
4. Revoke/disconnect/update external agents and guest certs safely; drain workflow leases, avoid double effect and retain recovery state. Deactivation of a feature must not leave orphaned secret, device task or accepted external callback.
5. Application rollback uses compatible schema and previous exact image/config after explicit review; do not blindly roll back already executed business actions or downgrade key/material/Outbox schema in ways that lose data.
6. Production activation only after operator/security/owner signed commissioning record. Developer MCP command success is never production access/evidence.

## Observability and audit operations
Preserve HooshiX ADR-0044 structured allowlist JSON logs, Micrometer/OpenTelemetry tracing, Collector, Prometheus/Alertmanager, Loki/Tempo/Grafana and off-host security audit. Add low-cardinality metrics: workflow run state/duration/age, task queue depth/lease expiry, tool/provider failure class and cost, per-tenant fairness *without tenantId in metric labels*, device connection/VM session readiness/reconnect/denials, approval backlog/expiry, inference queue/GPU token throughput, object store errors, index staleness, egress block decisions and retention backlog. Safe trace correlation uses opaque IDs without converting trace/baggage into auth/business authority. Logs must never contain raw prompts, screenshots, tokens, guest credentials, human MFA evidence, email contents, API keys or decoded full document text.

## SLO and benchmark protocol
Define measured targets per workload on selected hardware; do not copy standalone EAAP aspirational 10k devices or imaginary 'infinite scale' as currently supported capacity. Capture: interactive BFF p50/p95/p99 by route, Authorization current hard deadline and fail closed; workflow accepts/s and active/waiting counts with restart latency, worker dispatch p95; endpoint concurrent connections and task RTT with offline/reconnect; VM session warm-up, semantic action success by application/OS; provider/local model latency, tokens/sec and GPU memory, browser sessions; memory recall QPS/ACL and index lag; audit/evidence ingest/storage; per-tenant quota saturation and noisy-neighbor isolation. Load with existing services and telemetry on same single server, reserve measured headroom, no weak security tradeoff for target RPS. HA target separately tested for node/DB/broker/gateway/inference failure and zonal partition.

## Availability and disaster recovery
Map owned Postgres DBs and Flyway, Kafka topic/Outbox/Inbox/offsets, Redis (security-critical), key ring/OpenBao, workflow execution histories, versioned definitions, device identity cert/revocation, object evidence, memory/vector indexes, model assets/config and signed offline bundle into recovery manifest. Define per-store RPO/RTO consistent with existing HooshiX cold-DR and future HA policy; backup encrypted and off-host with tested restore. Restore sequence: trusted identity/keys/time -> DBs and event reconciliation -> authorization/policy -> workflow engine fencing -> connector and device certificate validation -> replay Outbox/Inbox -> index rebuild -> reopen routing. No replay of ambiguous external effect; compare prior idempotency evidence and reconnect generation. Test tenant deletion/legal hold restore reconciliation; redact audit and restore logs.

## Air-gap checklist
Preload signed container/model/package bundles, private registry, offline mirrors, local DNS/NTP/CA/SSO, local scanner/advisory database update procedure, no remote OCSP/telemetry/license dependency unless explicitly replaced by approved offline mechanism, and default-deny egress rules. Execute login → create worker → local-model-only workflow → VM guest enrollment/action → human approval → replay/audit → backup → offline signed update/rollback **in isolated network**. Packet capture and DNS log show no prohibited outbound attempt; verify credential and model signature rotation offline. Failure to load a cloud adapter is allowed only if routing fails closed with correct user-facing reason.

## Operational runbooks to be completed per deployed capability
Worker stuck/recover; workflow dead-letter/manual reconciliation; external provider quota/outage; guest VM identity compromise/revoke/rotate; host device gateway saturation; locked/no GUI session; approval expiry/forged event; memory index replay/delete; connector SSRF response; long-lived signed artifact and TLS/cert expiry; object-store/DB restore; offline model signature mismatch; multi-tenant isolation incident. Each includes owner, dashboard/alert, safe diagnostics, containment, tenant communication, recovery/verification, data/cost impact and postmortem evidence.

## Go/no-go
No production EAAP traffic unless accepted exact-digest release/admission, zero critical tenant/identity/egress/secret findings, current MFA/JIT and RLS evidence, actual end-to-end workflow/VM/local model/approval tests appropriate to claimed edition, confirmed capacity/headroom, backup/restore, incident runbook and approved operator/security record. Report each deployment profile and OS capability separately.
